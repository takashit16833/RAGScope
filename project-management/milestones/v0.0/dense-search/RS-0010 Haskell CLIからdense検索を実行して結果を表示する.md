# RS-0010 Haskell CLIからdense検索を実行して結果を表示する

## 目的

v0.0の最小のdense検索経路を利用者が実行できる状態にするためには、Haskell CLIから質問文を入力し、質問Embeddingの取得、PostgreSQL / pgvectorでの検索、上位チャンクの表示までを一連の操作としてつなぐ必要がある。

このTicketでは、Haskell CLIへ検索コマンドを追加し、RS-0008の質問Embedding取得処理とRS-0009のexact vector searchを順番に呼び出す。検索結果は、利用者が取得内容を確認できるように、順位、距離または類似度、元文書を識別する情報、`chunkIndex`、チャンク本文を人が読める形式で標準出力へ表示する。

さらに、前のEpicで実装した固定Markdown文書の取り込みとEmbedding保存を含め、文書取り込みから検索結果表示までをローカル環境で再実行できる手順を整え、v0.0のend-to-end動作を確認する。

## 実装メモ

- CLIは利用者向けの入口と処理の組み立てだけを担当し、質問Embedding生成やDB検索の詳細を重複実装しない。
- 検索コマンドはRS-0008とRS-0009で分離した処理をアプリケーション層から順番に呼び出す。
- v0.0では、質問文をコマンド引数として1件受け取る`ragscope search "<質問文>"`に固定する。複数質問や対話入力は扱わない。
- CLI parser library、command型、関数名などの局所的な選択はコードを正本とする。
- 正常な検索結果は標準出力、入力エラーや外部サービス・DBの失敗は標準エラー出力へ表示する。
- エラー表示には内部例外や認証情報をそのまま露出させず、利用者が失敗した処理段階を識別できる情報を含める。
- 検索結果の本文は省略せず表示してよい。結果同士を見出しや区切り線などで分け、順位とmetadataの対応を曖昧にしない。
- CLIの正確な利用方法は実装と`--help`を正本とし、READMEにはv0.0を再実行するために必要な最小手順だけを記載する。
- end-to-end確認では、RS-0001からRS-0009までで実装した処理を通常の手順で使用する。テストのためだけの手作業によるDB直接登録を、v0.0の再実行手順には含めない。
- end-to-end確認に使用する固定Markdown文書は、RS-0002の固定ルールによって2件以上のチャンクが生成される内容とする。候補が1件しかない状態を、順位付き検索の確認とはしない。
- 関連チャンクが上位に含まれることは、v0.0の経路が意味的な検索として接続されたことを確認するsmoke testとし、検索品質が十分であることや最適であることは主張しない。
- v0.0ではローカル同期実行に限定し、処理時間の最適化、retry、実行履歴の保存は後続Milestoneで扱う。
