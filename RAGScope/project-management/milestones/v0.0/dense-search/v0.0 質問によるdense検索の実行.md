# v0.0 質問によるdense検索の実行

## 能力

Haskell CLIから質問を入力し、文書チャンクのEmbedding生成時と同じEmbedding modelを利用して質問のEmbeddingを生成できる。

生成した質問Embeddingを使って、PostgreSQL / pgvectorに保存済みの文書チャンクをexact vector searchで検索し、質問に近い上位チャンクを順位とともにHaskell CLIへ表示できる。

## Milestoneでの役割

v0.0では、固定Markdown文書の取り込みから、質問に近い文書断片の表示までをつなぐ、最小のdense検索経路をローカル環境で完成させる。

このEpicはv0.0の出口を担当する。前のEpicで保存した文書チャンクとEmbeddingを検索対象とし、Haskellが質問入力と検索処理全体を制御する。AI推論サービスは質問のEmbeddingを生成し、PostgreSQL / pgvectorは質問Embeddingと保存済みEmbeddingの距離に基づいて上位チャンクを取得する。

回答生成、検索結果をcontextとしてLLMへ渡す処理、引用、検索品質の評価、検索結果や実験結果の永続化は、このEpicでは扱わず後続Milestoneで追加する。

## 完了条件

- [ ] Haskell CLIから空でない質問文を入力できる
- [ ] HaskellからHTTP / JSONでAI推論サービスへ質問文を渡し、質問のEmbeddingを受け取れる
- [ ] 質問Embeddingが、保存済みの文書チャンクEmbeddingと同じEmbedding modelおよび同じvector次元で生成される
- [ ] 質問Embeddingを使用し、PostgreSQL / pgvectorで近似検索indexを使用しないexact vector searchを実行できる
- [ ] 検索結果を質問との近さに従って順位付けし、固定件数の上位チャンクを取得できる
- [ ] 各検索結果について、順位、距離または類似度、元文書を識別する情報、文書内での順序、チャンク本文をHaskell CLIへ表示できる
- [ ] 質問文から質問Embeddingの生成、exact vector search、上位チャンク表示までを一連の処理として実行できる
- [ ] 空の質問、AI推論サービスを利用できない場合、質問Embeddingの生成に失敗した場合、PostgreSQLへ接続できない場合、検索に失敗した場合を、正常終了と区別して確認できる
- [ ] 保存済みの文書チャンクを使用した正常系と主要な異常系を、テストまたは実行によって確認できる
- [ ] 固定Markdown文書の取り込みから検索結果表示までを、定めた手順でローカル環境から再実行できる
