# v0.0 文書チャンクのEmbedding要求をtimeoutと安全なretryで制御する

## 能力

HaskellからAI推論サービスへ文書チャンクのEmbeddingを要求するoperationについて、規定した時間内に完了しない処理をtimeoutとして扱い、一時的失敗かつ再試行安全な場合にだけretryできる。

retryを行わない失敗、retry後の成功、試行上限へ達した失敗を区別し、共通エラーと構造化ログを通じて原因と試行経過を確認できる。

## Milestoneでの役割

HaskellからAI推論サービスへの文書Embedding要求は、v0.0で最初にtimeoutとretryを適用する具体的な外部operationである。このoperationを無制限に待機させたり、すべての失敗へ一律にretryを適用したりすると、停止時間の増大、無意味な再実行、元の原因の隠蔽につながる。

このEpicは、RS-0012で定義する文書Embedding生成APIとエラー契約を前提に、operation固有のretry / timeout設計と必要な最小範囲のexecutorを作成する。RS-0004はこの制御基盤を利用して実際のHTTP / JSON通信を実装する。

このEpicで作るexecutorは、利用箇所のない汎用retry frameworkではない。後続operationへ適用する場合は、副作用と再試行安全性を個別に確認し、自然に共有できる部分だけを共通部品として利用する。

## 完了条件

- [ ] 文書チャンクのEmbedding要求を対象としたretry / timeoutの現在設計が、機能別設計書として定義されている
- [ ] operationの境界、副作用、再試行安全性、timeout対象、retry対象と非対象が説明されている
- [ ] 試行回数、待機、時間制限、最終失敗の扱いが曖昧なく定義されている
- [ ] Haskellから利用できる必要最小限のretry executorとtimeout制御が実装されている
- [ ] 一時的失敗かつ再試行安全な場合だけretryし、それ以外の失敗を直ちに返せる
- [ ] timeout、retry後の成功、試行上限到達、retryしない失敗を、共通エラーと構造化ログで区別して確認できる
- [ ] executor単体の正常系・異常系と、RS-0004から利用する統合境界を自動テストで確認できる
- [ ] RS-0004が独自のretry loopを実装せず、このEpicの成果物を利用できる
