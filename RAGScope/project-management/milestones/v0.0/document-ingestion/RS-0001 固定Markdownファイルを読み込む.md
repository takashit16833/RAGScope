# RS-0001 固定Markdownファイルを読み込む

## 目的

v0.0で文書をチャンク化し、Embedding生成と検索へ渡すためには、最初に処理対象となるMarkdown文書の本文をHaskellから取得できる必要がある。

このTicketでは、RS-0011で作成した文書処理設計に従い、あらかじめ指定した固定パスのMarkdownファイルを1件読み込む。ファイル全体の本文を、後続のチャンク化処理から利用できる`Text`として取得する文書取り込みの入口を実装する。

## 前提

- [RS-0011 固定Markdown文書の取り込みとチャンク化を設計する](<./RS-0011 固定Markdown文書の取り込みとチャンク化を設計する.md>)が完了している
- `docs/design/文書処理設計.md`に、文書読み込みの責務、入出力、エラー・境界条件が記載されている

## 完了条件

- [ ] 読み込み確認に使用するUTF-8のMarkdownファイルが1件用意されている
- [ ] Haskellから指定した固定パスのMarkdownファイルを読み込める
- [ ] 見出し、Markdown記法、空行、改行を含むファイル全体の本文を`Text`として取得できる
- [ ] 読み込んだ本文へ正規化、Markdown記法の除去、前後空白の削除を行わず、入力内容を保持できる
- [ ] 読み込んだ本文が表示処理の内部だけに閉じず、呼び出し元へ返され、後続のチャンク化処理から利用できる
- [ ] 存在しないファイルを指定した場合、正常終了と区別できる形で読み込み失敗を確認できる
- [ ] 正常系とファイルが存在しない場合の異常系を、自動テストで確認できる
- [ ] 実装で具体化または変更された文書読み込みの現在設計が、`docs/design/文書処理設計.md`へ反映されている
- [ ] 実装と文書処理設計に解消していない差異がない
- [ ] プロジェクトで定めたテストコマンドを実行し、追加したテストを含めて成功する

## 対象外

- Markdown本文のチャンク分割
- CLI引数や設定ファイルによる入力パスの変更
- 複数ファイルまたはディレクトリ単位の読み込み
- TXT、PDF、画像など、Markdown以外の文書形式への対応
- Frontmatter、見出しなどのMarkdown構造の解析
- 改行コードやUnicodeの正規化
- 文書や本文に対する永続的な識別子・versionの付与
- Embedding生成
- PostgreSQLへの保存
- 検索処理

## 実装メモ

- 実行時の入力先は、文書処理設計で定めたv0.0用の固定パスとする。
- ファイルを読み込む処理は、テストと後続処理から利用できる関数として分離し、本文を`Text`で呼び出し元へ返す。
- 読み込み関数が`FilePath`を受け取り、アプリケーション側が固定パスを渡す構成としてよい。正確な型と関数名はコードを正本とする。
- 手動確認のため本文を標準出力へ表示してもよいが、表示できることだけを完了とはしない。
- テスト用Markdownファイルには、少なくとも見出し、複数段落、Markdown記法、空行を含め、読み込み前後の本文が一致することを確認する。
- Haskellの実行・テストに必要なプロジェクト構成がまだ存在しない場合は、このTicketを実行可能にする最小限の構成だけを作成する。
- 初期設計を変更する必要が生じた場合は、理由と後続Ticketへの影響を確認してから`文書処理設計.md`を更新する。
