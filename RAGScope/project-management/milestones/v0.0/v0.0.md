# v0.0 — 最小のdense検索を実行できる

## 目標

少量の固定Markdown文書を取り込み、固定ルールでチャンク化し、Embeddingを保存する。Haskell CLIから質問を入力し、質問に近い文書断片をexact vector searchで取得して表示できる、最小のdense検索経路をローカル環境で動作させる。あわせて、共通エラー・構造化ログ契約と契約を利用する各コンポーネントの最小基盤を整え、retry / timeoutは共通原則を定めたうえで、具体的な外部operationに必要な範囲だけ導入する。

## 対象範囲

- 少量の固定Markdown文書の読み込み
- Haskellによる固定ルールでのチャンク分割
- AI推論サービスによる文書チャンクと質問のEmbedding生成
- PostgreSQL / pgvectorへの文書チャンクとEmbeddingの保存
- Haskell CLIからの質問入力
- pgvectorを使用したexact vector search
- 検索結果となる上位チャンクのCLI表示
- ローカル環境での文書取り込みから検索結果表示までの一連の実行
- v0.0の各コンポーネントで共通利用するエラー表現と構造化ログの最小契約
- 構造化ログのserialized shapeを定義するJSON Schemaと、各実装で共有する代表的なfixture
- 契約を利用する各コンポーネントの構造化ログ基盤と、正常なCLI出力・HTTP応答から分離したローカル向けログ出力
- retry / timeoutを一時的失敗かつ再試行安全な処理に限定し、具体的な利用箇所が存在しない汎用executorを先行実装しない共通原則
- HaskellからAI推論サービスへ文書チャンクのEmbeddingを要求するoperationに必要となるretry / timeoutの機能別設計と最小実装

## 対象外

- TXT、PDF、画像など、固定Markdown以外の文書形式への対応
- 文書、文書集合、チャンク条件、Embedding条件のバージョン管理
- 正規化規則、offset、EvidenceSpanによる元文書への厳密な追跡
- 評価データ、検索指標、実験結果の保存・比較、Markdown / CSVレポート
- PostgreSQL全文検索、hybrid検索、reranking
- 回答生成、構造化引用、no-answer判定
- HNSW / IVFFlatなどの近似検索index
- AWSへの配置、CloudWatchへのログ収集、保持期間、alarmなどのAWS固有運用
- 本格的なtracing、性能集計
- 本格的なWeb UI、認証、ストリーミング、batch、非同期job
- v0.5以降で決定するtracingの正確な相関規則と、batch・非同期job固有の再実行・重複防止方式
