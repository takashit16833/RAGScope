# v0.0 共通エラーと構造化ログによる実行追跡

## 能力

v0.0の各処理が、失敗を正常結果と区別できる共通エラー契約を利用し、処理の進行と失敗を共通形式の構造化ログとして出力できる。

ローカル実行では、利用者へ返す正常出力とログを分離し、同じ実行に関係するイベントと失敗原因を識別して確認できる。

## Milestoneでの役割

v0.0では、文書読み込み、Python AI Serviceとの通信、PostgreSQL処理などを順次実装する。各機能が独自のエラー表現やログ形式を作ると、後続機能での追跡と保守が難しくなり、共通化時に広範囲な修正が必要になる。

このEpicは、文書処理の実装へ着手する前に、共通エラーと構造化ログの現在設計を定め、Haskellから利用できる最小基盤を実装する。各機能で発生する具体的なエラー、出力するイベント、Python AI ServiceやPostgreSQLとの境界への適用は、関係する機能設計と実装Ticketで具体化する。

retry / timeoutはログとは別の実行制御として扱い、このEpicではoperation固有のPolicyやexecutorを実装しない。

## 完了条件

- [ ] 共通エラー契約と構造化ログの現在設計が、機能別設計書として定義されている
- [ ] 内部エラー、利用者向けのエラー表示、HTTPなどの境界で受け渡す失敗、構造化ログイベントの責務が区別されている
- [ ] Haskellから共通エラーと構造化ログを利用できる最小基盤が実装されている
- [ ] ローカル実行で、正常出力とログを分離して出力できる
- [ ] 同じ実行に関係するイベントを識別し、処理の開始・完了・失敗を確認できる
- [ ] 構造化ログのschemaと主要な異常系を、自動テストまたは実行によって確認できる
- [ ] 文書処理設計と後続機能設計が、共通契約を参照して機能固有のエラーとログを定義できる
