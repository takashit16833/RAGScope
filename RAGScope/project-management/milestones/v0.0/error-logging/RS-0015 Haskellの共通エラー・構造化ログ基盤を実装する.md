# RS-0015 Haskellの共通エラー・構造化ログ基盤を実装する

## 目的

RS-0014で定義した共通エラー契約と構造化ログを、文書処理以降のHaskell実装から実際に利用できる最小基盤として提供する必要がある。

このTicketでは、共通エラーの表現、構造化ログイベント、相関情報、JSON出力、ローカル向けsink、テスト用sinkを実装する。特定機能のエラーやログを作り込むのではなく、RS-0011、RS-0001および後続機能が共通契約へ従って具体化できる土台を完成させる。

## 前提

- [RS-0014 共通エラーと構造化ログを設計する](<./RS-0014 共通エラーと構造化ログを設計する.md>)が完了している
- `docs/design/エラー・ログ設計.md`に、v0.0で実装する契約とローカル出力方針が記載されている

## 完了条件

- [ ] 設計に従った共通エラーのHaskell型と、正常結果から失敗を区別して扱うための境界が実装されている
- [ ] 共通Envelope、実行Context、イベント固有Payloadを表現できる構造化ログのHaskell型が実装されている
- [ ] event名、level、component、operation、error code、追加contextを設計に従って表現できる
- [ ] 1イベントを識別する情報と、同じローカル実行に属するイベントを識別する相関情報を生成・引き継ぎできる
- [ ] 構造化ログを1イベント1行のJSON Linesへencodeできる
- [ ] 該当しないoptional項目が設計に従って省略され、異なるイベントの項目を1つの巨大なnullable recordへ集約していない
- [ ] ローカル向けsinkが構造化ログをstderrへ出力し、利用者へ返す正常結果をstdoutへ出力できる
- [ ] business logicが具体的なstderr処理へ直接依存せず、sinkを差し替えられる
- [ ] 自動テストから出力イベントを検査できるin-memoryまたは同等のテスト用sinkが実装されている
- [ ] 文書本文、secret、認証情報など、設計で記録対象外とした情報を不用意に出力しない
- [ ] 共通エラーと主要な構造化ログeventについて、JSON出力、相関情報、level、エラー情報、optional項目の扱いを自動テストで確認できる
- [ ] stdoutとstderrが混在しないことを、テストまたは代表的な実行によって確認できる
- [ ] 実装で具体化または変更された現在設計が`docs/design/エラー・ログ設計.md`へ反映されている
- [ ] 実装と`エラー・ログ設計.md`に解消していない差異がない
- [ ] プロジェクトで定めたHaskell側のテストコマンドを実行し、追加したテストを含めて成功する

## 対象外

- retry / timeoutのPolicyとexecutor
- CloudWatchへの送信、AWS SDK依存、log groupや保持期間の設定
- 本格的なtracing、性能集計、batch、非同期job固有の相関情報
- 実験状態とエラーのPostgreSQLへの永続化
- 独立した共通packageへの分離

## 実装メモ

- 最初はRAGScopeのHaskell application内部に、責務の明確な共通moduleとして実装する。利用実態が生じる前に独立packageへ分離しない。
- 正確なmodule名、型名、constructor、JSON field名は、設計との整合を保ちつつコードを正本とする。
- business logicは意味のあるeventを渡し、JSON化、時刻付与、ID生成、出力先の処理を可能な範囲で境界へ分離する。
- golden testを採用する場合は、時刻や生成IDなど実行ごとに変化する値を安定して検査できる方法を用意する。
