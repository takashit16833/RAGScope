# ログ・イベント設計

> [!abstract] この文書の役割
> RAGScopeで観測する情報をSpan、Span属性、OpenTelemetry LogsのEventRecord、通常のLogRecordのどこへ置くかと、失敗時の重複記録を防ぐ共通規則を定義する。

## 1. 基本方針

RAGScopeで新たに定義する名前付きイベントは、OpenTelemetry LogsのEventRecordとして記録する。RAGScope独自のSpan Eventは使用しない。

観測したい情報は次の基準で配置する。

| 情報 | 表現 |
|---|---|
| 開始から終了まで時間を持つ処理 | Span |
| そのSpanの処理を説明する値で、独立した時刻を持つ必要がない情報 | Span attributes |
| ある時点で起きた、名前を付けて検索・集計したい出来事や状態遷移 | EventRecord |
| 名前付きイベントにする必要がない診断メッセージ | 通常のLogRecord |

OpenTelemetry Semantic Conventionに該当する標準Eventや属性がある場合はそれを優先する。Spanの開始・終了・Status・属性だけで同じ事実を十分に確認できる場合、同じ事実を表すEventRecordを追加しない。

## 2. EventRecordを作成する条件

typed failureが発生したことだけではEventRecordを作成しない。retry、timeout、fallbackの途中で一度失敗したことだけでも、共通のEventRecordを自動生成しない。

状態遷移そのものを名前付きの出来事として後から識別する必要があり、Spanの最終結果だけではその出来事を表せない場合にEventRecordを定義する。

RAGScope独自EventRecordが必要な場合、そのイベントを所有するUseCaseまたは内部処理の設計で少なくとも次を定義する。

- 何が起きたイベントか
- 記録する条件
- EventName
- timestampが表す時点
- Severity
- attributes
- 失敗イベントで必要な場合の`error.type`変換

RAGScope独自EventNameは`ragscope.*`名前空間を使用する。文書ID、件数、error値など実行ごとに変わる値をEventNameへ埋め込まず、attributesへ置く。

## 3. Traceとの関連付けとSeverity

EventRecordと通常のLogRecordは、OpenTelemetryが保持する現在のTrace Contextによって対応するTrace / Spanへ関連付ける。RAGScope独自のTraceId / SpanId保持構造を別に設けない。

SeverityはOpenTelemetryのSeverityNumberとして扱う。RAGScope共通の`debug` / `info` / `warn` / `error` / `fatal`という固定5段階契約は設けない。SeverityからSpan StatusやApplicationの処理結果を導出しない。

## 4. 失敗とException

RAGScope独自Spanでtyped failureが最終結果になった場合は、まずSpan Statusと`error.type`によって処理自身の失敗を表す。同じ失敗を示すEventRecordを自動では追加しない。

unexpected同期Exceptionが追跡対象の処理から外へ伝播する場合、対応するSpanのError記録に加えて、LogsへExceptionを表すEventRecordを1件だけ記録し、Exceptionを再throwする。

同じExceptionについてUseCase Span、handler相当の境界、entry Spanの各層で重複EventRecordを作成しない。より下位の標準計装が同じException EventRecordをすでに記録している場合、上位層では重複して記録しない。

採用するHaskell SDKのSpan helperなどがExceptionを自動的にSpan Eventへ記録し、LogsのException EventRecordと同じ事実を二重記録する場合は、OpenTelemetry Adapter側でその自動Span Eventを抑制し、Logs側の1件にそろえる。

## 5. 外部表現と出力基盤

LogRecordのProcessor、Exporter、batching、flush / shutdown、送信はOpenTelemetry SDKへ委ねる。RAGScope共通の`LogRecord`型、Logging Runtime、Sink、JSON serializationを、OpenTelemetry Logsと並行する共通基盤として持たない。

RS-0021までに検討したRAGScope独自のログJSON SchemaやSQLite投影は、OpenTelemetry Logsを採用する現在設計の共通外部表現には使用しない。将来、RAGScopeがOpenTelemetryとは別に安定した外部ログ形式を公開する要求が生じた場合は、その要求を持つ契約として別途設計する。
