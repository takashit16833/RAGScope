# 実行追跡設計

RAGScopeの実行追跡について、システム全体で共有する契約と、各コンポーネントでその契約を実現する詳細設計を読み分けるための索引である。

| 文書 | 確認したいこと |
|---|---|
| [実行追跡・構造化ログ契約設計](../実行追跡・構造化ログ契約設計.md) | 1回の利用者操作を1つの`trace`として扱う境界、`span`の親子関係、Span Status、コンポーネント間のTrace Context引き継ぎ、構造化ログとの共通規則 |
| [RAGScopeアプリケーション実行追跡詳細設計](./RAGScopeアプリケーション実行追跡詳細設計.md) | RAGScopeアプリケーションでObservability・Tracing・OpenTelemetry Adapter・Logging Runtimeをどう接続し、current Trace Contextをどう管理するか |

実行追跡はRAGScopeアプリケーションだけの概念ではない。RAGScopeアプリケーションからAI推論サービスへ処理を依頼する場合も、共通契約に従ってTrace Contextを引き継ぎ、同じ`trace`を継続する。

各コンポーネント固有の詳細設計書は、そのコンポーネントで共通契約を実現する責務、境界、依存関係などをMarkdownで管理する具体的な必要が生じた場合に置く。正確な型、関数、module、package、設定、依存関係、テストケースを機械可読に表現できる場合は、コード、設定、テストなどを正本とする。
