# ユースケース詳細設計

> [!abstract] この文書の役割
> [ユースケース基本設計](./ユースケース基本設計.md)で定義するユースケースの実行境界、成功、最終失敗と、各[機能設計](./features/README.md)で定義する具体的な失敗を、RAGScopeアプリケーションのHaskell実装でどのように表現し、ユースケース境界で受け渡すかを定義する。
>
> 個々のユースケースで何を成功・最終失敗とみなすかは基本設計、具体的にどのような失敗があるかは各機能設計を正本とする。正確なHaskell型・constructor・関数定義は実装コードを正本とし、この文書では実装が守る表現と受け渡しの契約を扱う。

## 1. 成功と最終失敗の受け渡し

RAGScope Applicationとの呼び出し境界では、ユースケースの成功と最終失敗を明示的な戻り値として区別する。Haskell実装では`Either`を使用し、最終失敗を`Left`、成功を`Right`として表す。

```mermaid
flowchart LR
    Application["RAGScope Application"] -->|"UseCaseを呼び出す"| UseCase["UseCase"]
    UseCase --> Result{"実行結果"}
    Result -->|"成功"| Right["Right result"]
    Result -->|"最終失敗"| Left["Left failure"]
    Right --> Application
    Left --> Application
```

通常のユースケース失敗を例外によってRAGScope Applicationへ伝達しない。ユースケース内部で失敗を短絡的に伝播させる実装には`ExceptT`を使用できるが、その基底Monadはこの設計では固定しない。

例外は通常のユースケース失敗とは別の実行上の事象として扱う。同期例外・非同期例外をどこで捕捉し、ユースケース結果や観測情報とどう関係付けるかは、例外処理の設計で定める。

## 2. 機能固有の失敗の表現

具体的にどの状況を失敗とするかは、その処理を担当する各機能設計で定める。この詳細設計では、それらの失敗をユースケース境界でどのようなHaskellの値として表現するかを定める。

各ユースケースは、最終失敗へ至る機能固有の理由をユースケース固有の失敗型で表す。失敗型のconstructorは、各機能設計で定義された失敗を区別し、RAGScope Applicationがその最終失敗を扱うために必要な情報を保持できる。

dense検索では、この失敗型を`DenseSearchFailure`とする。

```text
各機能設計で定義した具体的な失敗
                ↓
       <Feature>Failure
                ↓
     UseCaseの最終失敗
                ↓
      ApplicationへLeft
```

Feature固有の失敗型は`RAGScope.<Feature>.Failure`に置く。どの失敗条件にどのconstructorを対応させるかは各機能設計と実装を整合させ、正確な型定義とconstructorは実装コードを正本とする。

## 3. `ErrorType`への変換契約

ユースケースが最終失敗として返す失敗型は、失敗値だけから対応する`ErrorType`を一意に得られるものとする。この共通変換契約を`ToErrorType`で表す。

```text
Feature固有failure
      │
      │ ToErrorType
      ▼
   ErrorType
```

`ToErrorType`の変換には、RAGScope Applicationの実行状況など追加のContextを要求しない。同じ失敗値からは同じ`ErrorType`が得られる純粋な変換とする。

ユースケース外のfailureも、そのfailureを扱う境界で`ErrorType`が必要と決まった場合には同じ契約を利用できる。`ToErrorType`を利用すること自体は、そのfailureを構造化ログへ記録することや`trace`・`span`で追跡することを意味しない。

`ErrorType`の意味と、span・構造化ログで同じ失敗理由を共有する規則は[実行追跡・構造化ログ契約設計](./logging/実行追跡・構造化ログ契約設計.md)を参照する。

## 4. `ErrorType`と`ToErrorType`の配置

`ErrorType`と`ToErrorType`は、Logging、Tracing、Observability、Feature固有failureのいずれにも所有させず、共通local package `ragscope-error`へ置く。

```text
ragscope-error
└─ public: main
   └─ RAGScope.ErrorType
      ├─ ErrorType
      └─ ToErrorType

ragscope
└─ private: ragscope-features
   └─ RAGScope.<Feature>.Failure
      ├─ <Feature>Failure
      └─ ToErrorType instance
```

`ToErrorType <FeatureFailure>`のinstanceは、Feature固有failure型を定義する`RAGScope.<Feature>.Failure`へ置く。これにより、Feature自身が共通の失敗理由への分類を定義し、instanceをorphanにしない。

`ragscope-features`はこの契約を利用するため`ragscope-error`へ依存する。Observability、Tracing、Loggingなど他packageの依存は、それぞれが`RAGScope.ErrorType`を直接importする必要がある場合に各設計で定める。

`ErrorType`の内部表現はこの文書では固定しない。
