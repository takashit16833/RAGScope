# 構造化ログ設計

RAGScopeの構造化ログについて、共通契約、RAGScopeアプリケーション内のevent変換、外部表現の責務を読み分けるための索引である。

| 文書 | 確認したいこと |

| [RAGScopeアプリケーション構造化ログイベント変換詳細設計](./RAGScopeアプリケーション構造化ログイベント変換詳細設計.md) | RAGScopeアプリケーションで所有者定義eventを`ToLogSpec`で`LogSpec`へ変換し、実行時情報を加えて`LogRecord`を作る境界 |
| [構造化ログ外部表現共通設計](./構造化ログ外部表現共通設計.md) | RAGScope定義の外部形式で共通して使う項目名・値表現、Trace Contextの有無、属性を形式間でどう維持するか |

構造化ログは実行追跡の下位概念ではなく、`trace`に属するイベントだけにも限定しない。利用者操作の処理中に起きたイベントは対応する`span`へ関連付け、コンポーネントの起動・終了など特定の利用者操作へ属さないイベントはTrace Contextを持たない構造化ログとして記録できる。実行追跡そのもののコンポーネント別詳細設計は[実行追跡設計](../tracing/README.md)から参照する。

各コンポーネントの正確な内部型、発生元の値、ログ受付・出力の境界、設定、ログ基盤自身の実装固有の失敗処理は、コード、設定、Schema、テストなどの機械可読な正本で管理する。機能処理に属する具体的なイベント、属性、`error_type`、機能処理の`span`は、それらを定義する各機能設計を正本とする。利用インターフェースやコンポーネントのライフサイクルに属する具体的なイベントは、それぞれを担当する設計・契約またはコード・設定・テストを正本とする。

各外部表現設計は、[実行追跡・構造化ログ契約設計](../実行追跡・構造化ログ契約設計.md)の論理情報と、[構造化ログ外部表現共通設計](./構造化ログ外部表現共通設計.md)の共通情報・属性の規則を前提に、それぞれの形式固有の構造を定める。ある外部表現を経由して別の外部表現を定めない。
