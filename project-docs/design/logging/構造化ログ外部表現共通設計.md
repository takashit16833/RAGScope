# 構造化ログ外部表現共通設計

> [!abstract] この文書の役割
> [実行追跡・構造化ログ契約設計](./実行追跡・構造化ログ契約設計.md)で定義する構造化ログを、RAGScopeが定めるnon-OTLPの外部形式へ出力するときに共通して使用する項目名と値表現、および属性を形式間でどう維持するかを定義する。各形式の構造、符号化、省略方法は、それぞれの外部表現設計が担当する。

## 1. 共通外部表現

### 1.1 共通情報

外部形式を切り替えても、構造化ログの共通情報は同じ外部項目名と値表現を使用する。

| 論理情報 | 外部項目名 | 共通の値表現 |
|---|---|---|
| 発生時刻 | `timestamp` | UTCのRFC 3339形式`YYYY-MM-DDTHH:MM:SS[.fraction]Z`で表す。小数秒が0なら小数部を省略し、0でなければ末尾の0を付けない |
| 発生元 | `component` | 文字列 |
| イベント名 | `event` | 論理契約で定めたイベント名を文字列として表す |
| 重要度 | `level` | 論理契約で定めた重要度を文字列として表す |
| メッセージ | `message` | 論理上存在する場合、その文字列を表す |
| `TraceId` | `trace_id` | 16 byteの`TraceId`を32文字の小文字16進数で表す |
| `SpanId` | `span_id` | 8 byteの`SpanId`を16文字の小文字16進数で表す |

### 1.2 属性

属性は、各機能設計で定めた論理上の属性名を外部表現でも同じ名前で表す。属性値は論理上の型と値を維持し、各外部形式から同じ論理値へ戻せるように表す。

`error_type`とドメイン参照も他の属性と同じ属性として扱い、共通外部項目へ昇格させない。

RAGScope定義の外部形式を切り替えても、共通情報の項目名と値表現、および属性名と論理上の型・値は変えず、形式固有の構造と符号化だけを変更する。

## 2. 責務と正本

| 正本 | 担当すること |
|---|---|
| [実行追跡・構造化ログ契約設計](./実行追跡・構造化ログ契約設計.md) | 構造化ログが持つ論理情報、その意味、必須・任意、属性、`TraceId`・`SpanId`の意味 |
| この文書 | RAGScopeが定めるnon-OTLP外部表現で共通する項目名と値表現、属性名と論理上の型・値を形式間で維持する規則 |
| 各外部表現設計 | 共通情報と属性を各形式へ配置する方法、形式固有の型・構造・符号化・省略方法・出力単位 |
| Schemaなどの機械可読な契約 | 採用した外部形式の正確な項目、型、必須条件、文字列形式 |
