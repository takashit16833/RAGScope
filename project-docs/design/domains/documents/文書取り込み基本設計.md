# 文書取り込み基本設計

> [!abstract] この文書の役割
> MarkdownまたはTXTの技術文書を取り込み、文書集合・文書・文書バージョンの関係を保ったまま、正規化済み本文を持つ追跡可能な版として保存する機能の責務と境界を定義する。
> 具体的な処理順序、検証、失敗時の扱い、不変条件は[文書取り込み詳細設計](./文書取り込み詳細設計.md)で定義する。

## 1. 目的と適用範囲

文書取り込みは、外部の技術文書をRAGScope内の文書バージョンとして保存する。

| 扱うこと | 扱わないこと |
|---|---|
| Markdown / TXT文書を取り込み、形式を検証する | PDF、OCR、画像、複雑なレイアウトを解析する |
| 文書集合、文書、文書バージョンの関係を保って保存する | 文書を文書チャンクへ分割する |
| 同じ文書の内容が変わった場合に、新しい文書バージョンとして区別する | 過去の文書バージョンを上書きする |
| 後続処理が位置を参照するときの基準となる正規化済み本文を確定する | 検索用データを生成する、検索する、回答を生成する |

この機能は`REQ-DOC-001`を実現し、`REQ-DOC-004`のうち文書集合・文書・文書バージョンを識別して異なる版を混同せず管理する部分を担う。また、`REQ-DOC-003`と`REQ-NF-TRACE-002`に必要な追跡の起点を作る。

## 2. 責務と境界

文書取り込みは、対象の技術文書から内容を取得し、UTF-8の文字列へ変換して正規化規則を適用し、文書集合・文書・文書バージョンの関係を保って保存するところまでを担当する。

文書チャンク化、検索用データ生成、検索、回答生成は担当しない。

## 3. 概念上の入出力

| 区分 | 内容 |
|---|---|
| 入力 | 取り込むMarkdown / TXTの技術文書と、その文書を文書集合・文書として識別するために必要な情報 |
| 前提 | 対象の技術文書を取得でき、文書集合・文書として扱うために必要な情報がそろっている |
| 成功結果 | 文書集合と文書に関連付けて保存した文書バージョン |
| 失敗結果 | 文書取り込みを完了できないことを表す処理失敗 |

技術文書をファイルパス、バイト列、文字列、読み取り処理などのどの形で受け取るかは未決定である。CLI / APIの具体的な入力形式も未決定である。

## 4. 主要な設計

### 4.1 文書と版を区別する

文書は、同じ技術文書の複数の版を継続して関連付ける単位として扱う。内容が変わった場合は過去の文書バージョンを書き換えず、新しい文書バージョンとして区別する。

文書集合の中で文書を一意に識別する具体的な識別子と一意性制約は未決定である。

### 4.2 正規化済み本文を共通の参照基準にする

各文書バージョンは1つの正規化済み本文を保持する。文書チャンクと正解根拠は、この正規化済み本文を共通の位置参照の基準として使用する。

文書取り込みでは正規化規則を適用する。具体的な正規化規則は未決定であり、決定状態と処理規則は[文書取り込み詳細設計](./文書取り込み詳細設計.md)で扱う。

## 5. 成功結果の返却と後続利用

文書取り込みは、保存済みの文書バージョンを成功結果として呼び出し元へ返す。文書取り込み自身は文書チャンク化を開始しない。

文書チャンク化を行う処理は、この保存済みの文書バージョンを入力として使用し、その文書バージョンが保持する正規化済み本文を参照する。元の入力から本文を作り直さない。

文書バージョンをどの型や識別子として返すかは未決定である。

## 6. 詳細設計と機械可読な正本

具体的な処理順序、文書バージョンの再利用、正規化済み本文の検証、保存単位、失敗時の扱い、Observability、不変条件は[文書取り込み詳細設計](./文書取り込み詳細設計.md)を正本とする。

正確な型、識別子、一意性制約、トランザクション境界、利用インターフェースの入力形式は現時点では未決定である。実装時はコード、migration、OpenAPIなどの機械可読な正本で定義する。
