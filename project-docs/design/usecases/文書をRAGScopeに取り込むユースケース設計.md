# 文書をRAGScopeに取り込むユースケース設計

> [!abstract] この文書の役割
> 利用者がMarkdown / TXTの技術文書をRAGScopeへ取り込むユースケースの入力、成功結果、処理の流れ、再実行、失敗時の扱いを定義する。
> 文書取り込みの内部処理は、文書取り込みの機能設計を正本とする。

## 1. 目的

このユースケースの目的は、利用者が指定したMarkdown / TXTの技術文書を、文書集合と文書に関連付いた文書バージョンとして保存することである。

このユースケースは、`REQ-DOC-001`を実現し、`REQ-DOC-004`のうち文書集合・文書・文書バージョンを識別して異なる版を混同せず管理する部分を扱う。

## 2. 入力と成功結果

RAGScopeアプリケーションは次の情報を入力として受け取る。

| 入力 | 内容 |
|---|---|
| 技術文書 | RAGScopeへ取り込むMarkdown / TXTの文書 |
| 文書集合・文書を識別するための情報 | 対象の文書集合と文書を特定するための情報 |

成功結果は、文書集合と文書に関連付けて保存した文書バージョンである。RAGScopeアプリケーションは、その文書バージョンを呼び出し元へ返す。

## 3. 処理の流れ

1. RAGScopeアプリケーションが、技術文書と文書集合・文書を識別するための情報を受け取る。
2. [文書取り込み](../domains/documents/文書取り込み基本設計.md)を実行する。
3. 文書取り込みが返した保存済みの文書バージョンを、このユースケースの成功結果として呼び出し元へ返す。

文書取り込みの処理規則は、[文書取り込み詳細設計](../domains/documents/文書取り込み詳細設計.md)を正本とする。

## 4. 再実行

| 状態 | 扱い |
|---|---|
| 同じ文書について、同じ正規化規則から得た正規化済み本文が既存の文書バージョンと一致する | 既存の文書バージョンを再利用して成功結果として返す |
| 同じ文書について、正規化済み本文が既存の文書バージョンと異なる | 新しい文書バージョンを保存して成功結果として返す |

新しい文書バージョンを作る場合、過去の文書バージョンは上書きしない。

## 5. 失敗時の扱い

文書取り込みが最終的に文書バージョンを返せない場合、このユースケースは最終失敗を呼び出し元へ返す。

文書取り込みで発生する処理失敗と再試行条件は[文書取り込み詳細設計](../domains/documents/文書取り込み詳細設計.md)を正本とする。UseCaseの最終失敗に関する共通規則は[RAGScopeアプリケーション失敗設計](../RAGScopeアプリケーション失敗設計.md)に従う。

## 6. 未決定事項

現在の正本で、このユースケースについて未決定なのは次のとおりである。

- 技術文書をこのユースケースへ渡す形。ファイルパス、バイト列、文字列、読み取り処理などのどれを使用するか
- 文書集合と文書を特定するために入力する正確な項目
- 成功結果と最終失敗を表す正確な型

これらは未決定であり、このユースケース設計から推測して固定しない。
