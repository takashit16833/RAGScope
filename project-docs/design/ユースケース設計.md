# ユースケース設計

> [!abstract] この文書の役割
> 利用者がRAGScopeへ依頼するトップレベルな操作の考え方と、1回の実行境界を定義する。

## 1. ユースケースの考え方

- 利用者の目的単位の操作を1つのユースケースとして扱う。
- 複数の内部処理から構成されても、それぞれを自動的に別ユースケースとはしない。
- CLIとAPIで同じ目的の操作を実行する場合は、同じユースケースとして扱う。
- 1回の実行は、RAGScopeアプリケーションが入力を受け取ってから、成功結果または最終失敗を呼び出し元へ返すまでとする。

CLI引数やAPI Schemaなど、インターフェース固有の契約はこの文書では定義しない。
