# ユースケース設計

> [!abstract] この文書の役割
> 利用者がRAGScopeへ依頼するトップレベルな操作の考え方と、1回の実行境界を定義する。

## 1. ユースケースの考え方

この文書では、利用者がRAGScopeへ依頼する目的単位の操作をユースケースとする。

文書バージョンの作成、文書チャンク化、検索用データ生成などは、ユースケースを構成する内部処理として扱う。利用者が各内部処理を個別に操作することを、ユースケースの前提にはしない。

同じ利用者操作をRAGScope CLIまたはRAGScope APIから実行しても、同じユースケースとして扱う。CLIの引数やAPIのSchemaなど、インターフェース固有の契約はこの文書では定義しない。

1回のユースケース実行は、RAGScopeアプリケーションがユースケースの入力を受け取った時点で開始し、成功結果を作るか最終失敗を返して呼び出し元へ制御を戻した時点で終了する。

## 2. ユースケース一覧

| ユースケース | 利用者の目的 |
|---|---|
| 文書を検索可能にする | Markdown / TXTの技術文書を取り込み、指定した条件で検索に使用できる状態にする |

文書の内容変更、分割条件の変更、検索用データ生成条件の変更は、現在の設計では「文書を検索可能にする」の再実行として扱う。
