# ユースケース設計

> [!abstract] この文書の役割
> 利用者がRAGScopeへ依頼するトップレベルな操作と、操作ごとの入力・結果・主要な処理、1回の実行がどこからどこまでかを定義する。

## 1. ユースケースと実行境界

この文書では、利用者がRAGScopeへ依頼するトップレベルの操作をユースケースとする。Embedding生成、データベース検索、文書チャンク化など、ユースケースから呼び出す処理は、そのユースケースを構成する内部処理として扱う。

各ユースケースの「入力」には、RAGScope Applicationがユースケースを呼び出すときに渡す値を定義する。「結果」には、ユースケースがRAGScope Applicationへ返す値、またはRAGScope Applicationへ制御を戻す前に作る状態を定義する。

1回のユースケース実行は、RAGScope Applicationがユースケースを呼び出した時点で開始し、その呼び出しからRAGScope Applicationへ制御が戻った時点で終了する。RAGScope Applicationがユースケースを呼び出さなかった場合、ユースケース実行は発生しない。CLIやAPIによる入力の受け取りと変換、ユースケースの呼び出し終了後に行う表示やHTTPレスポンスへの変換は、ユースケース実行に含めない。

Observabilityで使用する[Invocation](../RAGScope用語集.md#invocation)は、このユースケース実行より広い範囲である。InvocationとTraceの対応は[実行追跡設計](./observability/実行追跡設計.md)を正本とする。

ユースケースが「結果」に定義した値をRAGScope Applicationへ返した場合、または「結果」に定義した状態を作ってからRAGScope Applicationへ制御を戻した場合を、そのユースケース実行の成功とする。どちらも行わずにユースケース実行が終了した場合を失敗とする。内部処理で失敗が発生しても、ユースケースが再試行または代替処理を行い、最終的に「結果」に定義した値を返すか状態を作った場合は成功とする。失敗をHaskellの型、例外、その他の仕組みでどのように表現するかは、この文書では定義しない。

同じ利用者操作をCLI、APIなど異なるインターフェースから実行しても、同じユースケースとして扱う。
