# ユースケース設計

> [!abstract] この文書の役割
> 利用者がRAGScopeへ依頼するトップレベルな操作と、操作ごとの入力・結果・主要な処理、1回の実行がどこからどこまでかを定義する。

## 1. ユースケースと実行境界

この文書では、利用者がRAGScopeへ依頼するトップレベルの操作をユースケースとする。Embedding生成、データベース検索、文書チャンク化など、ユースケースから呼び出す処理は、そのユースケースを構成する内部処理として扱う。

各ユースケースの「入力」には、RAGScopeアプリケーションがユースケースを呼び出すときに渡す値を定義する。「結果」には、ユースケースがRAGScopeアプリケーションへ返す値、またはRAGScopeアプリケーションへ制御を戻す前に作る状態を定義する。

1回のユースケース実行は、RAGScopeアプリケーションがユースケースを呼び出した時点で開始し、その呼び出しからRAGScopeアプリケーションへ制御が戻った時点で終了する。RAGScopeアプリケーションがユースケースを呼び出さなかった場合、ユースケース実行は発生しない。CLIやAPIによる入力の受け取りと変換、ユースケースの呼び出し終了後に行う表示やHTTPレスポンスへの変換は、ユースケース実行に含めない。

Observabilityで使用する[Invocation](../RAGScope用語集.md#invocation)は、このユースケース実行より広い範囲である。InvocationとTraceの対応は[実行追跡設計](./observability/実行追跡設計.md)を正本とする。

ユースケースが「結果」に定義した値をRAGScopeアプリケーションへ返した場合、または「結果」に定義した状態を作ってからRAGScopeアプリケーションへ制御を戻した場合を、そのユースケース実行の成功とする。どちらも行わずにユースケース実行が終了した場合を失敗とする。内部処理で失敗が発生しても、ユースケースが再試行または代替処理を行い、最終的に「結果」に定義した値を返すか状態を作った場合は成功とする。失敗をHaskellの型、例外、その他の仕組みでどのように表現するかは、この文書では定義しない。

同じ利用者操作をCLI、APIなど異なるインターフェースから実行しても、同じユースケースとして扱う。

## 2. ユースケース

| ドメイン領域 | ユースケース | 利用者の目的 |
|---|---|---|
| 文書 | [文書を登録する](<#2.1.1 文書を登録する>) | Markdown / TXTの技術文書をRAGScopeへ登録または更新する |
| 文書 | [文書集合を管理する](<#2.1.2 文書集合を管理する>) | 検索や実験でまとめて扱う文書の集合を作り、所属を変更する |
| 文書 | [文書を検索可能にする](<#2.1.3 文書を検索可能にする>) | 登録済みの文書バージョンから、指定した検索方式に必要な検索用データを準備する |
| 検索・回答生成 | [dense検索する](<#2.2.1 dense検索する>) | 指定した検索対象から質問に近い文書チャンクを順位付きで取得する |

### 2.1 文書

#### 2.1.1 文書を登録する

| 項目 | 内容 |
|---|---|
| 目的 | Markdown / TXTの技術文書を文書と文書バージョンとして保存する |
| 入力 | 文書形式、文書内容、新規登録または更新の指定。更新時は対象文書と期待する現在の文書バージョン |
| 結果 | 登録対象の文書と文書バージョンを特定でき、正規化後の本文が保存されている |

主要な処理は次のとおりである。

1. [文書取り込み設計](./domains/documents/文書取り込み設計.md)に従い、文書をUTF-8として読み取り、本文を正規化して検証する。
2. [文書・文書バージョン管理設計](<./domains/documents/文書・文書バージョン管理設計.md>)に従い、新規文書として登録するか、期待する現在の文書バージョンを確認して既存文書を更新する。
3. 更新競合がなければ、文書と文書バージョンを特定できる結果を返す。

#### 2.1.2 文書集合を管理する

| 項目 | 内容 |
|---|---|
| 目的 | 検索や実験の対象としてまとめて扱う文書集合と、その所属関係を管理する |
| 入力 | 文書集合の作成、または既存の文書集合と文書に対する追加・除外の指定 |
| 結果 | 文書集合と文書の所属関係を取得できる状態で保存されている |

[文書・文書バージョン管理設計](<./domains/documents/文書・文書バージョン管理設計.md>)に従い、文書集合の作成、文書の追加、文書の除外を行う。文書集合の所属変更によって文書バージョンや検索用データは変更しない。

#### 2.1.3 文書を検索可能にする

| 項目 | 内容 |
|---|---|
| 目的 | 登録済みの文書バージョンを、指定した検索方式で利用できる状態にする |
| 前提 | 対象の文書バージョンが登録済みである |
| 入力 | 文書バージョン、分割条件、準備対象。全文検索ではtext search configuration、dense検索ではEmbeddingプロファイルID |
| 結果 | 指定したすべての検索用データ準備単位が`ready`になっている |

主要な処理は次のとおりである。

1. [文書分割設計](./domains/documents/文書分割設計.md)に従い、文書バージョンを分割条件に対応する文書チャンクへ分割する。
2. [検索用データ準備設計](./domains/documents/検索用データ準備設計.md)に従い、指定された検索方式に必要な検索用データだけを準備する。
3. 指定した検索用データ準備単位がすべて`ready`であることを確認する。

全文検索だけを指定した場合はEmbedding生成を行わない。複数の準備対象を指定し、一部だけが`ready`になった場合は、準備済み単位を保持するがユースケース全体は失敗とする。

### 2.2 検索・回答生成

#### 2.2.1 dense検索する

| 項目 | 内容 |
|---|---|
| 目的 | 指定した検索対象から質問に近い文書チャンクを順位付きで取得する |
| 前提 | [検索対象設計](<./domains/retrieval-generation/検索対象設計.md>)に従い、対象文書バージョンのdense検索の検索用データ準備単位がすべて`ready`である |
| 入力 | 空でない質問、文書集合に属する文書の現在の文書バージョン、または固定文書バージョン集合、分割条件、EmbeddingプロファイルID、正の`topK` |
| 結果 | 順位付きの文書チャンク。検索対象が空、または該当候補がない場合の0件も正常な結果として扱う |

主要な処理は次のとおりである。

1. 検索対象を具体的な文書バージョン集合へ解決し、必要なdense検索の検索用データ準備単位がすべて`ready`であることを確認する。
2. [Embedding生成設計](./Embedding生成設計.md)に従い、指定したEmbeddingプロファイルで質問Embeddingを生成する。
3. 質問Embeddingと同じプロファイルの文書チャンクEmbeddingだけを使ってvector searchする。
4. 検索結果を順位付きの文書チャンクとして返す。
