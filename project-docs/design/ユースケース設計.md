# ユースケース設計

> [!abstract] この文書の役割
> 利用者がRAGScopeへ依頼するトップレベルな操作の考え方と、個別ユースケース設計への入口を定義する。
> 各ユースケースの入力、成功結果、処理の流れ、再実行、失敗時の扱いは、個別のユースケース設計を正本とする。

## 1. ユースケースの考え方

この文書では、利用者がRAGScopeへ依頼する目的単位の操作をユースケースとする。

文書取り込み、文書チャンク化、検索用データ生成などの機能は、ユースケースから必要に応じて呼び出す内部処理として扱う。利用者が各内部機能を個別に操作することを、ユースケースの前提にはしない。

同じ利用者操作をRAGScope CLIまたはRAGScope APIから実行しても、同じユースケースとして扱う。CLIの引数やAPIのSchemaなど、インターフェース固有の契約はこの文書では定義しない。

1回のユースケース実行は、RAGScopeアプリケーションがユースケースの入力を受け取った時点で開始し、成功結果を作るか最終失敗を返して呼び出し元へ制御を戻した時点で終了する。

## 2. ユースケース一覧

| ユースケース | 利用者の目的 | 設計書 |
|---|---|---|
| 文書をRAGScopeに取り込む | Markdown / TXTの技術文書を取り込み、保存済みの文書バージョンとして扱える状態にする | [文書をRAGScopeに取り込むユースケース設計](./usecases/文書をRAGScopeに取り込むユースケース設計.md) |

同じ文書の内容が変わった場合に、新しい文書バージョンとして取り込む操作は「文書をRAGScopeに取り込む」の再実行として扱う。
