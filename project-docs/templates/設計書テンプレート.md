# 設計書テンプレートの選択

> [!abstract] この文書の役割
> 機能別設計書を新規作成するときに、設計対象の中心となる問いに合うテンプレートを選び、対象に合わせて構成を整えるための入口である。

| テンプレート | 中心となる問い | 主な対象 |
|---|---|---|
| [処理・振る舞い設計書テンプレート](./処理・振る舞い設計書テンプレート.md) | 何が、どの順序で、どの条件に従って処理されるか | 入出力、処理段階、分岐、正常系・異常系、後続処理への受け渡し |
| [構造・契約設計書テンプレート](./構造・契約設計書テンプレート.md) | 何を共有し、それぞれが何を意味し、どの規則を守るか | 項目、語彙、識別子、形式、公開範囲、不変条件、機械可読な正本 |

## 選択方法

1. 読者が最初に答えを得たい問いを確認する。
2. 主となる性質に対応するテンプレートを1つ選ぶ。
3. もう一方の性質も必要な場合は、必要な節だけを追加する。
4. 2つのテンプレートを単純に結合した全部入りの文書にしない。

## テンプレートの使い方

> [!important] テンプレートは帳票ではない
> テンプレートの見出しは初期構成であり、完成文書の固定章立てではない。

テンプレートを挿入した後は、設計対象と読者の問いに合わせて次を行う。

- 不要な見出しを削除する。
- 近接して読む必要がある節を統合する。
- 必要に応じて見出しを並べ替え、設計対象に合う名称へ変更する。
- 関連する要求、上位設計、機械可読な正本への導線を、本文を中断しない自然な場所へ必要最小限置く。
- テスト観点、将来事項、変更時の注意は、本文とは異なる設計固有の情報がある場合だけ追加する。
- 同じ規則を文章、表、図、概要、詳細で繰り返さない。

どちらにも自然に適合しない場合は、文書の分割または設計対象の再定義を検討する。将来の可能性だけを理由に3つ目のテンプレートを先行作成しない。

`システムアーキテクチャ.md`はシステム全体を扱う特別な文書であり、いずれかの機能別設計テンプレートへ機械的に合わせない。

選択基準と運用規則の正本は、[RAGScope文書管理規約「4.5 機能設計の種類と構成」](<../rules/RAGScope文書管理規約.md#4.5 機能設計の種類と構成>)とする。
