## 主要な差分

|領域|現行設計|差分|
|---|---|---|
|適用範囲|RAGScopeアプリケーション側が中心|AI推論サービスを含む技術非依存の共通契約へ変更が必要|
|ADR|ADR-0001を現行判断として参照|ADR-0002へ切り替え、ADR-0001は歴史的参照に限定する必要がある|
|共通エラー|category、code、message、cause、contextを定義済み|内容は概ね利用可能。コンポーネント共通の意味と個別実装の境界を補足する|
|構造化ログ|Envelope・Context・Payloadを概念定義済み|serialized shapeの正本となるJSON Schemaが存在しない|
|Schema仕様|`schema_version: 1`だけ定義|JSON Schema draft、配置、Schemaファイルのversion管理が未定|
|fixture|なし|適合・不適合fixtureと、両実装で共有する方針が必要|
|相関情報|CLIの`execution_id`のみ|コンポーネント境界での伝播、service-scoped event、diagnostic requestとの区別が不足|
|ID・時刻|opaque ID、UTCとだけ記載|IDの文字列表現、timestamp形式、timezone表現が未定|
|logger失敗|sink失敗と再帰出力禁止を記載|encode失敗、元operation失敗の保持、failing sinkの共通テスト方針が不足|
|情報保護|記録禁止情報とallowlistを定義済み|概ね利用可能|
|retry / timeout|共通エラーと分離済み|概ね利用可能|
|将来境界|CloudWatch、tracing、batchを後続へ分離済み|概ね利用可能|

特に、現行設計はRAGScopeアプリケーション向けと明記され、ADR-0001を参照しています。[エラー・ログ設計「1.2 適用範囲」](<./docs/design/エラー・ログ設計.md#1.2 適用範囲>)、[エラー・ログ設計「2.2 上位設計」](<./docs/design/エラー・ログ設計.md#2.2 上位設計>)

これは、複数コンポーネントで契約を共有すると定めた[ADR-0002「決定」](<./docs/adr/ADR-0002 共通実行基盤の契約とコンポーネント実装を分離する.md#決定>)および[システムアーキテクチャ「3.4 共通実行基盤の責務境界」](<./docs/design/システムアーキテクチャ.md#3.4 共通実行基盤の責務境界>)と一致していません。

## そのまま再利用できる内容

以下は判断自体に大きな問題がないため、簡潔にして残せます。

- 共通エラーのcategoryと基本構造
- 公開messageと内部causeの分離
- エラーcategoryとログlevelの分離
- stdout／stderrとJSON Linesの方針
- sinkをbusiness logicから分離する方針
- 機密情報のallowlist方式
- retry／timeoutをoperation固有設計へ分離する方針
- CloudWatch、tracing、batchを後続Milestoneへ送る境界
