# RS-0007 AI推論サービスで質問Embeddingを生成する

## 目的

v0.0で文書チャンクを質問との意味的な近さによって検索するためには、利用者が入力した質問文を、保存済みの文書チャンクのEmbeddingと比較できる質問Embeddingへ変換する必要がある。

このTicketでは、RS-0013で設計・更新した質問Embeddingの契約に従い、AI推論サービスへ質問Embedding生成機能を実装する。RS-0003で採用したものと同じEmbeddingモデル、リビジョン、Tokenizerおよび固定生成条件を使用し、文書用と質問用で異なる入力規則がある場合は、AI推論サービス内で質問用の規則を適用する。

RAGScopeアプリケーションから質問Embedding生成を依頼された場合は、RS-0013で確定した通信契約に従って受け取ったTrace Contextから同じ`trace`を継続し、呼び出し元`span`を親とするAI推論サービス側の新しい`span`の中で質問Embedding生成を実行する。

## 前提

- [RS-0013 質問によるdense検索を設計する](<./RS-0013 質問によるdense検索を設計する.md>)が完了している
- `design/Embedding生成設計.md`とOpenAPIに、質問Embeddingの入力規則、API契約、Trace Context伝播が反映されている
- `RS-0003`が完了し、文書チャンクのEmbedding生成に使用するモデルと固定生成条件、およびAI推論サービス側の実行追跡基盤が実装されている

## 完了条件

### モデルと入力規則

- [ ] RS-0003で採用したものと同じEmbeddingモデル、リビジョン、Tokenizerを利用して質問Embeddingを生成できる
- [ ] 設計で固定した質問用の入力規則、プーリング、最大入力長、切り詰め（truncation）、ベクトル正規化が適用される
- [ ] 文書用と質問用のEmbedding生成をAPI契約上で区別し、質問文へ文書用の接頭辞（prefix）または指示文（instruction）を誤って適用しない

### 質問Embeddingの生成と実行追跡

- [ ] AI推論サービスが、1件の空でない質問文を受け取り、その質問文に対応する質問Embeddingを返せる
- [ ] 受け取ったTrace Contextから同じ`TraceId`を使用し、呼び出し元`SpanId`で識別される`span`を親とする質問Embedding生成側`span`を開始できる
- [ ] 質問Embedding生成側`span`を処理結果が確定した境界で終了し、その処理自身の最終結果に従ってSpan Statusを`Error`または`Unset`として扱える
- [ ] 機能設計で記録対象とした構造化ログをcurrent `span`の`TraceId`・`SpanId`へ関連付け、同じ失敗を`span`とログの両方へ記録する場合は同じ`error_type`を使用できる
- [ ] 生成される質問Embeddingが、保存済みの文書チャンクのEmbeddingと同じベクトル次元を持つ
- [ ] 生成される質問Embeddingに、`NaN`や無限大など利用できない値が含まれないことを確認できる
- [ ] 使用中のモデルID、リビジョン、Embeddingの出力次元を既存の確認方法から取得できる

### エラーと検証

- [ ] 空文字または空白だけの質問文、不正なリクエストを、正常なEmbedding生成と区別できるエラーとして扱える
- [ ] モデルを読み込めない場合と質問Embeddingの生成に失敗した場合を、正常終了と区別して確認できる
- [ ] リクエストの検証、Trace Context受領と親子関係、質問用入力規則の適用、ベクトル次元、有限値、主要な異常系を自動テストで確認できる
- [ ] 採用した実モデルを使用し、質問文から文書チャンクのEmbeddingと比較可能なEmbeddingを生成できることを結合テストまたは実行によって確認できる

### 正本と整合

- [ ] 実装された質問Embedding APIとOpenAPIのリクエスト・レスポンス、Trace Context伝播、必須条件、エラー形式が一致している
- [ ] 実装で具体化または変更された質問Embedding生成の現在設計が`design/Embedding生成設計.md`へ反映されている
- [ ] 実装、OpenAPI、Embedding生成設計、実行追跡・構造化ログ契約に解消していない差異がない
- [ ] プロジェクトで定めたAI推論サービス側のテストコマンドを実行し、追加したテストを含めて成功する

## 実装メモ

- AI推論サービスはAI推論だけを担当し、質問の永続化、dense検索、RAGScope全体の処理順序を管理しない。
- 質問Embedding生成には、設計とOpenAPIで定めた既存APIの拡張または再利用方法を使用する。
- Trace Contextの正確な通信表現はRS-0013で確定したOpenAPIなどの通信契約を使用し、このTicketで独自形式を追加しない。
- 文書用と質問用で接頭辞や指示文が異なるモデルでは、呼び出し側が加工済み文字列を組み立てるのではなく、AI推論サービスが用途に応じた固定規則を適用する。
- 質問文そのものに不要な正規化や改変を行わない。ただし、空文字または空白だけの入力を無効として検証するための判定は行ってよい。
- RS-0003で読み込み済みのモデルを再利用し、質問処理のたびにモデルを再読み込みしない。
- 自動テストではEmbeddingの浮動小数点値そのものの完全一致へ過度に依存せず、Trace Context親子関係、入力用途、次元、有限値、エラー分類などの契約を主に確認する。
- 初期設計またはOpenAPIを変更する必要が生じた場合は、実装だけを先行させず、同じ変更で正本を更新する。
