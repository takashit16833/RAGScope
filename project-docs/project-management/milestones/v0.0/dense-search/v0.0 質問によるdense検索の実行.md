# v0.0 質問によるdense検索の実行

## 能力

RAGScope CLIから質問を入力し、文書チャンクのEmbedding生成時と同じEmbeddingモデルを利用して質問Embeddingを生成できる。

生成した質問Embeddingを使って、PostgreSQL / pgvectorに保存済みの文書チャンクをexact vector searchで検索し、質問に近い上位文書チャンクを順位とともにRAGScope CLIへ表示できる。

## Milestoneでの役割

### dense検索経路の出口

v0.0では、固定Markdown文書の取り込みから、質問に近い文書チャンクの表示までをつなぐ、最小のdense検索経路をローカル環境で完成させる。このEpicは、その出口を担当する。

### コンポーネントの責務

前のEpicで保存した文書チャンクとEmbeddingを検索対象とし、RAGScopeアプリケーションが質問入力と検索処理全体を制御する。AI推論サービスは質問Embeddingを生成し、PostgreSQL / pgvectorは質問Embeddingと保存済みの文書チャンクのEmbeddingの距離に基づいて上位文書チャンクを取得する。

RAGScopeアプリケーションとAI推論サービスのHTTP境界ではOpenTelemetry Trace Contextを伝播し、PostgreSQL、HTTP client / serverなどSemantic Conventionが適用できる処理は標準計装を優先する。CLIからの1回の呼び出しは[実行追跡設計](../../../../design/observability/実行追跡設計.md)に従う1つのInvocationとして追跡する。

### 後続Milestoneとの境界

回答生成、検索結果を回答生成用文書チャンクとして選択する処理、引用、検索品質の評価、検索結果や実験結果の永続化は、このEpicでは扱わず後続Milestoneで追加する。

## 完了条件

### 質問入力とEmbedding生成

- [ ] RAGScope CLIから空でない質問文を入力できる
- [ ] RAGScopeアプリケーションからHTTP / JSONでAI推論サービスへ質問文を渡し、質問Embeddingを受け取れる
- [ ] 質問Embeddingが、保存済みの文書チャンクのEmbeddingと同じEmbeddingモデルおよび同じベクトル次元で生成される
- [ ] RAGScopeアプリケーションからAI推論サービスへTrace Contextを伝播し、同じTraceでHTTP client / server処理を追跡できる

### PostgreSQLによるdense検索

- [ ] 質問Embeddingを使用し、PostgreSQL / pgvectorで近似検索インデックスを使用しないexact vector searchを実行できる
- [ ] 検索結果を質問との近さに従って順位付けし、固定件数の上位文書チャンクを取得できる
- [ ] PostgreSQL処理に適用できるSemantic Conventionを利用し、同じDB処理を表す独自Spanを重複して追加していない

### CLI表示と一連の実行

- [ ] 各検索結果について、順位、距離または類似度、元文書を識別する情報、文書内での順序、文書チャンク本文をRAGScope CLIへ表示できる
- [ ] 質問文から質問Embeddingの生成、exact vector search、上位文書チャンク表示までを一連の処理として実行できる
- [ ] 固定Markdown文書の取り込みから検索結果表示までを、定めた手順でローカル環境から再実行できる

### 失敗・Observability・検証

- [ ] 空の質問、AI推論サービスを利用できない場合、質問Embeddingの生成に失敗した場合、PostgreSQLへ接続できない場合、検索に失敗した場合を、正常終了と区別できる具体的なerrorとして扱える
- [ ] CLI Invocation、UseCase、HTTP、DBのTrace / Span構造が[実行追跡設計](../../../../design/observability/実行追跡設計.md)と矛盾せず、失敗した子Spanだけを理由に親SpanをErrorへしていない
- [ ] 保存済みの文書チャンクを使用した正常系と主要な異常系を、テストまたは実行によって確認できる
