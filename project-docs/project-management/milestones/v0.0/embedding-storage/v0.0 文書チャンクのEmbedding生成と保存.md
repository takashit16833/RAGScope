# v0.0 文書チャンクのEmbedding生成と保存

## 能力

前のEpicで生成した文書チャンクを、v0.0で採用する1つのEmbedding modelを利用してAI推論サービスからEmbeddingへ変換し、元の文書チャンクとの対応を保ったままPostgreSQL / pgvectorへ保存できる。

保存した文書チャンクとEmbeddingを、後続のdense検索処理から検索対象として利用できる。

## Milestoneでの役割

v0.0では、固定Markdown文書から生成したチャンクをvectorとして保存し、質問Embeddingとの距離を比較することで、意味的に近いチャンクを取得する最小のdense検索経路を完成させる。

このEpicは、文書チャンクを作成する最初のEpicと、質問から検索を実行する最後のEpicの間を担当する。RAGScopeアプリケーションが処理全体とデータの対応関係を管理し、AI推論サービスが文書チャンクのEmbeddingを生成し、PostgreSQL / pgvectorが文書チャンクとEmbeddingを永続化する。

RAGScopeアプリケーションからAI推論サービスへ文書チャンクのEmbeddingを要求するoperationでは、共通エラー・構造化ログ基盤を利用する。RS-0004へ着手する前に、別Epicでoperation固有のretry / timeout設計と必要最小限のexecutorを完成させ、RS-0004ではその成果物を実際のHTTP / JSON通信へ統合する。

質問文の入力と質問Embedding生成、exact vector search、検索結果のCLI表示は、後続の「v0.0 質問によるdense検索の実行」Epicで扱う。

Embedding modelや生成条件のバージョン管理、複数モデルの比較、Embedding cache、非同期・大規模batch処理、HNSW / IVFFlatなどの近似検索indexは、このEpicでは扱わず後続Milestoneで追加する。

## 完了条件

- [ ] v0.0で使用するEmbedding modelが1つ決定され、AI推論サービスからローカル環境でロードできる
- [ ] AI推論サービスが文書チャンクの本文を受け取り、各チャンクに対応するEmbeddingを生成できる
- [ ] RAGScopeアプリケーションからHTTP / JSONでAI推論サービスへ文書チャンクを渡し、生成されたEmbeddingを受け取れる
- [ ] RAGScopeアプリケーションからAI推論サービスへの文書チャンクのEmbedding要求に、機能別設計で定めたtimeoutと安全なretryが適用されている
- [ ] retryを行わない失敗、retry後の成功、試行上限到達、timeoutを、共通エラーと構造化ログで区別して確認できる
- [ ] 入力した文書チャンクと返却されたEmbeddingの対応関係を保持できる
- [ ] 同じEmbedding modelから生成されるvectorの次元が一定であり、PostgreSQL / pgvectorへ保存できる
- [ ] 文書チャンクの本文、元文書を識別する情報、文書内での順序、対応するEmbeddingを関連付けて保存できる
- [ ] 保存した文書チャンクとEmbeddingをPostgreSQLから読み出し、後続のdense検索で使用できる状態であることを確認できる
- [ ] AI推論サービスを利用できない場合、Embedding生成に失敗した場合、または保存に失敗した場合を、正常終了と区別して確認できる
- [ ] 文書チャンクの受け渡しからEmbedding生成・保存までの一連の正常系と主要な異常系を、テストまたは実行によって確認できる
