# v0.0 — 最小のdense検索を実行できる

## 目標

少量の固定Markdown文書を取り込み、固定ルールで文書チャンクへ分割して、文書チャンクのEmbeddingを保存する。RAGScope CLIから質問を入力し、近似インデックスを使わないベクトル検索（exact vector search）で質問に近い文書チャンクを取得・表示できる、最小のdense検索経路をローカル環境で動作させる。

あわせて、OpenTelemetry Trace / Logsを前提に実行追跡・構造化ログアーキテクチャを定め、契約を利用する各コンポーネントの最小基盤を整える。再試行・タイムアウトは共通原則を定め、具体的な外部処理に必要な範囲だけ導入する。

## 対象範囲

### dense検索の最小経路

- 少量の固定Markdown文書の読み込み
- RAGScopeアプリケーションによる固定ルールでの文書チャンク分割
- AI推論サービスによる文書チャンクのEmbeddingと質問Embeddingの生成
- PostgreSQL / pgvectorへの文書チャンクとEmbeddingの保存
- RAGScope CLIからの質問入力
- pgvectorを使用した、近似インデックスを使わないベクトル検索（exact vector search）
- 検索結果となる上位の文書チャンクのRAGScope CLIへの表示
- ローカル環境での文書取り込みから検索結果表示までの一連の実行

### 実行追跡・構造化ログ

- OpenTelemetry Trace / Logsを前提とした、v0.0で必要な実行追跡・構造化ログアーキテクチャ
- 契約を利用する各コンポーネントの実行追跡・構造化ログの最小基盤
- 正常なCLI出力・HTTP応答から分離した、ローカル環境向けのTelemetry確認手段

### 再試行・タイムアウト

- 再試行・タイムアウトを、一時的な失敗が発生し、かつ同じ処理を繰り返しても安全な場合に限定する共通原則
- 具体的な利用箇所がない汎用的な実行機構を先行実装しない方針
- RAGScopeアプリケーションからAI推論サービスへ文書チャンクのEmbeddingを要求する処理に必要な、再試行・タイムアウトの機能別設計と最小実装

## 対象外

- TXT、PDF、画像など、固定Markdown以外の文書形式への対応
- 文書、文書集合、チャンク条件、Embedding条件のバージョン管理
- 正規化規則、位置（`offset`）、`EvidenceSpan`による元文書への厳密な追跡
- 評価データ、検索指標、実験結果の保存・比較、Markdown / CSV形式のレポート
- PostgreSQL全文検索、hybrid検索、`reranking`
- 回答生成、構造化引用、回答不能（`no-answer`）判定
- HNSW / IVFFlatなどの近似検索インデックス
- AWSへの配置、CloudWatchへのログ収集、保持期間、アラームなどのAWS固有運用
- OpenTelemetry Collectorや外部Telemetry backendの本番環境構築
- 本格的なWeb UI、認証、ストリーミング、バッチ処理、非同期ジョブ

## 成功条件

### dense検索の最小経路

- [ ] RAGScopeアプリケーションで固定Markdown文書を読み込み、本文を後続処理へ渡せる
- [ ] 読み込んだ文書を固定ルールで文書チャンクへ分割できる
- [ ] AI推論サービスで文書チャンクのEmbeddingを生成できる
- [ ] 文書チャンクとEmbeddingをPostgreSQL / pgvectorへ保存できる
- [ ] RAGScope CLIから質問を入力し、質問Embeddingを生成できる
- [ ] pgvectorの近似インデックスを使わないベクトル検索（exact vector search）で、質問に近い上位の文書チャンクを取得できる
- [ ] 取得した上位の文書チャンクをRAGScope CLIへ表示できる
- [ ] 文書取り込みから検索結果表示までを、定めた手順でローカル環境から再実行できる

### 実行追跡・構造化ログ

- [ ] OpenTelemetry Trace / Logsを前提に、RAGScopeが必要とする実行追跡・構造化ログの全体アーキテクチャが定義されている
- [ ] 契約を利用する各コンポーネントで、それぞれの最小基盤を利用できる
- [ ] ローカルでは正常なCLI出力・HTTP応答とTelemetryが分離され、1回のユースケース実行についてコンポーネント境界を越えて一連の処理を追跡し、記録したログを対応する実行追跡情報と関連付けて確認できる
- [ ] 各機能設計で、採用した共通アーキテクチャに従って機能固有の実行追跡・ログ記録を具体化できる

### 再試行・タイムアウト

- [ ] 再試行・タイムアウトの共通原則がADRで確定し、各機能の対象処理について自動再試行の有無と理由を判断できる
- [ ] RAGScopeアプリケーションからAI推論サービスへ文書チャンクのEmbeddingを要求する処理について、必要な再試行・タイムアウトが機能別設計に基づいて実装・テストされる
- [ ] 各機能の設計で、発生するエラー、自動再試行の有無を説明できる
