# RS-0014 共通エラーと構造化ログを設計する

## 目的

v0.0では、文書読み込み、AI推論サービスとの通信、PostgreSQL処理など、異なる種類の処理と失敗を扱う。各実装Ticketが独自のエラー型、エラーコード、ログ項目、実行との関連情報を決めると、処理全体を追跡できず、後から共通化する際に広範囲な修正が必要になる。

このTicketでは、後続の共通基盤実装と機能実装に先立ち、複数のコンポーネントが利用できる、実装技術に依存しない共通エラー契約と構造化ログ契約を設計する。現在設計は`design/エラー設計.md`と`design/構造化ログ設計.md`へ分けて管理する。構造化ログをJSONへ変換したときの項目構成をJSON Schemaとして定義し、各実装で共有する代表的な検証用データ（fixture）を作成する。v0.0のローカル実行に必要な最小範囲を定義し、将来のHTTP、AWSでの収集、分散追跡（tracing）へ拡張できる境界を保ちつつ、現時点で使用しない詳細は固定しない。

## 実装メモ

- 設計書には、実装だけでは分かりにくい責務、契約、不変条件、処理フロー、変更時の注意を記載する。
- 正確な型定義やJSON変換のコードをMarkdownへ複製しない。
- v0.0では、CLIコマンドとサービスの生存期間を、実行との関連情報（Context）の具体的な対象として扱う。HTTPやバッチ処理の完全なスキーマを先回りして作らない。
- 将来の分散追跡へ拡張できる意図は残すが、現時点で`trace_id`やSpan構造を採用済みとして記載しない。

## 結果

### 設計と契約

- 複数コンポーネントが利用する、実装技術に依存しない共通エラー契約と構造化ログ契約を定義し、現在設計を`エラー設計.md`と`構造化ログ設計.md`へ分離した。
- 共通エラー、`LogEvent`、ログイベント組み立て処理（event builder）、ログ受付処理（logger）、出力判定（filter）、JSON変換（encoder）、出力処理（sink）、JSON復元処理（decoder）の責務と変換境界を定義した。
- 具体的な処理種別（`operation`）は各機能設計、共通の処理段階（`phase`）とログイベント名（`event`）の生成規則は構造化ログ設計を正本とし、処理種別とエラーコードを機能ごとの閉じた型として扱う方針を定めた。
- ローカル実行では、正常なCLI結果を標準出力、構造化ログを標準エラー出力へ分け、ログイベント1件を1行のJSONとして出力する方針を定めた。
- ログ受付処理自身のJSON変換・出力失敗、代替出力を採用しない方針、元の処理種別の失敗を上書きしない扱いを定めた。

### JSON Schemaと検証用データ

- JSONへ変換したときの項目構成の正本として`contracts/logging/v1/log-event.schema.json`を作成した。
- 共通項目、エラー分類（`category`）、ログレベル（`level`）、コンポーネント（`component`）、`execution`・`service`の実行との関連情報、エラー情報（Error）、UUIDv4、UTC時刻、識別子形式をDraft 2020-12で定義した。
- `contracts/logging/v1/fixtures/`へSchema適合例3件と不適合例10件を作成した。
- Draft 2020-12対応の検証処理でSchema自体を検査し、適合例3件の受理と不適合例10件の拒否を確認した。

### 後続Ticketへ渡す判断

- RS-0015とRS-0018は同じSchemaと検証用データを使用し、型、例外変換、ログイベント組み立て処理、ログ受付処理、JSON変換、出力処理を各コンポーネントで実装する。
- 1回のCLIコマンドでは、コンポーネント境界を越えて同じ`execution_id`を引き継ぐ。
- 各実装は、Schema適合だけでなく、ログイベント名と処理種別の対応、識別子の閉じた型、標準出力と標準エラー出力の分離、テスト用出力処理、失敗する出力処理をテストする。

### 後続機能で具体化する事項

- 機能固有の処理種別、ログ観測点、エラーコード、許可するPayloadとエラーの補助情報は、各機能の設計とコードで定義する。
- HTTPエラーレスポンスと`execution_id`の引き継ぎ方法は、API設計とOpenAPIで定義する。
- 再試行回数、タイムアウト値、再試行しても安全かどうかは、処理種別ごとに判断する。
- CloudWatchの具体設定はv0.1.5、分散追跡とバッチ処理・非同期ジョブの相関情報はv0.5以降で決定する。
