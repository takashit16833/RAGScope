# v0.0 共通エラーと構造化ログによる実行追跡

> [!note] 現在の設計
> このEpicは初期計画時の名称を維持しているが、RS-0023とADR-0006による再設計後は共通`RAGScopeError`やRAGScope独自の構造化ログ基盤を採用しない。現在の能力と完了条件はOpenTelemetry Observabilityを基準とする。

## 能力

v0.0の各処理について、処理の進行と失敗を後から確認でき、RAGScopeアプリケーションとAI推論サービスのコンポーネント境界を越えた一連の処理を追跡できる。

ローカル実行では、利用者へ返す正常なCLI出力・HTTP応答とTelemetryを分離し、Trace、Logs、MetricsをTempo、Loki、Prometheus、Grafanaで確認できる。

## Milestoneでの役割

### 機能実装より先に共通化する理由

v0.0では、文書読み込み、AI推論サービスとの通信、PostgreSQL処理などを順次実装する。各機能が独自のTrace Context管理やログ送信基盤を作ると、後続機能での追跡と保守が難しくなる。

### このEpicで整えるもの

このEpicでは、OpenTelemetryをObservability共通基盤として、Trace、Logs、Metricsの役割、RAGScopeとOpenTelemetryの責務境界、各コンポーネントの最小SDK基盤、ローカルでTelemetryを横断確認する構成を整える。

全体アーキテクチャは[RS-0023](<./RS-0023 OpenTelemetry Logsを前提に実行追跡・構造化ログアーキテクチャを再設計する.md>)と[Observability設計](../../../../design/observability/README.md)を正本とする。

### 後続機能へ委ねるもの

各機能で使用する具体的なSpan、EventRecord、属性、具体的なerror typeからTelemetryの`error.type`への変換は、その機能設計と実装Ticketで具体化する。RAGScopeアプリケーションからAI推論サービスへのTrace Contextの具体的な伝播は、そのHTTP通信を実装するTicketが担当する。

再試行・timeoutはTelemetryとは別の実行制御として扱う。具体的な対象、条件、試行回数、待機方法、timeout範囲は関係する機能設計と実装Ticketで定める。

## 完了条件

### Observabilityアーキテクチャ

- [x] RAGScope要求定義とシステム構造から、後から識別・確認する必要がある処理、出来事、失敗、コンポーネント間の関係が特定されている
- [x] OpenTelemetry Trace / Logs / Metricsへ委ねる責務と、RAGScopeが所有する処理制御・ドメイン結果・具体的なerror typeの境界が決定されている
- [x] Trace / Span、EventRecord / LogRecord、Metricsの役割分担と失敗のTelemetryへの反映が決定されている
- [x] ローカルbackendとしてTempo、Loki、Prometheus、Grafanaを使用することと、具体的な送信経路を配置実装へ委ねる境界が決定されている
- [x] ADR-0006、Observability設計群、システムアーキテクチャ、用語集が採用したアーキテクチャと整合している

### コンポーネントごとの最小基盤

- [ ] RAGScopeアプリケーションで、採用したアーキテクチャに従うOpenTelemetry最小基盤を利用できる
- [ ] AI推論サービスで、採用したアーキテクチャに従うOpenTelemetry最小基盤を利用できる
- [ ] 各コンポーネント固有の型、Telemetry利用境界、Adapter、設定、失敗処理がコード・設定・テストを正本として管理されている

### ローカル出力と実行追跡

- [ ] 正常なCLI出力・HTTP応答とTelemetryを分離できる
- [ ] 1つのInvocationについてRAGScopeアプリケーションとAI推論サービスを同じTraceで追跡できる
- [ ] Logsを対応するTrace / Spanへ関連付け、標準Metricが存在する範囲でMetricsも同じローカル環境から確認できる

### 検証と後続機能への引き渡し

- [ ] 各コンポーネントのOpenTelemetry基盤を主要な正常系・異常系の自動テストで確認できる
- [x] 後続機能が共通アーキテクチャを参照して機能固有のSpan、EventRecord、属性、`error.type`を具体化できる境界が提供されている
