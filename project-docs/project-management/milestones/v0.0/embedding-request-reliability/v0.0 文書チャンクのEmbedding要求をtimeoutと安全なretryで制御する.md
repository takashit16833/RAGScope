# v0.0 文書チャンクのEmbedding要求をtimeoutと安全なretryで制御する

## 能力

RAGScopeアプリケーションからAI推論サービスへ文書チャンクのEmbeddingを要求する処理種別（`operation`）について、規定した時間内に完了しない処理をタイムアウトとして扱い、一時的失敗かつ再試行しても安全な場合にだけ再試行できる。

再試行を行わない失敗、再試行後の成功、試行上限へ達した失敗を区別し、共通エラーと構造化ログを通じて原因と試行経過を確認できる。

## Milestoneでの役割

### 最初に実行制御を適用する処理

RAGScopeアプリケーションからAI推論サービスへの文書チャンクのEmbedding要求は、v0.0で最初にタイムアウトと再試行を適用する具体的な外部処理である。この処理を無制限に待機させたり、すべての失敗へ一律に再試行を適用したりすると、停止時間の増大、無意味な再実行、元の原因の隠蔽につながる。

### このEpicで整えるもの

このEpicは、RS-0012で定義する文書チャンクのEmbedding生成APIとエラー契約を前提に、処理種別固有の再試行・タイムアウト設計と必要な最小範囲の実行機構を作成する。RS-0004はこの制御基盤を利用して実際のHTTP / JSON通信を実装する。

### 共通化の境界

このEpicで作る実行機構は、利用箇所のない汎用的な再試行フレームワークではない。後続の処理種別へ適用する場合は、副作用と再試行安全性を個別に確認し、自然に共有できる部分だけを共通部品として利用する。

## 完了条件

### 処理種別と方針

- [ ] 文書チャンクのEmbedding要求を対象とした再試行・タイムアウトの現在設計が、機能別設計書として定義されている
- [ ] 処理種別の境界、副作用、再試行安全性、タイムアウト対象、再試行対象と非対象が説明されている
- [ ] 試行回数、待機、時間制限、最終失敗の扱いが曖昧なく定義されている

### 実行機構と失敗時の挙動

- [ ] RAGScopeアプリケーションから利用できる必要最小限の再試行の実行機構とタイムアウト制御が実装されている
- [ ] 一時的失敗かつ再試行しても安全な場合だけ再試行し、それ以外の失敗を直ちに返せる
- [ ] タイムアウト、再試行後の成功、試行上限到達、再試行しない失敗を、共通エラーと構造化ログで区別して確認できる

### 統合境界と検証

- [ ] 実行機構単体の正常系・異常系と、RS-0004から利用する統合境界を自動テストで確認できる
- [ ] RS-0004が独自の再試行処理を実装せず、このEpicの成果物を利用できる
