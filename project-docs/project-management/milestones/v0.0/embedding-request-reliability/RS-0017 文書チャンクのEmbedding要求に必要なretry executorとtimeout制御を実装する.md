# RS-0017 文書チャンクのEmbedding要求に必要なretry executorとtimeout制御を実装する

## 目的

RS-0016で定義した文書チャンクのEmbedding要求向けの再試行方針とタイムアウト規則を、RS-0004から利用できるRAGScopeアプリケーションの実行制御としてHaskellで実装する必要がある。

このTicketでは、対象の処理種別（`operation`）に必要な最小範囲の再試行の実行機構、タイムアウト制御、エラー分類との接続、試行を表す構造化ログイベントの出力を実装する。実際の文書チャンクのEmbedding生成APIのリクエスト・レスポンス変換や、文書チャンクとEmbeddingの対応検証はRS-0004に残す。このTicketでは、1回の試行を安全に制御する部品と統合境界を完成させる。

## 前提

- [RS-0016 文書チャンクのEmbedding要求に必要なretryとtimeoutを設計する](<./RS-0016 文書チャンクのEmbedding要求に必要なretryとtimeoutを設計する.md>)が完了している
- [RS-0015 RAGScopeアプリケーションの共通エラー・構造化ログ基盤を実装する](<../error-logging/RS-0015 RAGScopeアプリケーションの共通エラー・構造化ログ基盤を実装する.md>)が完了している
- `design/リトライ・タイムアウト設計.md`に、対象の処理種別の方針、タイムアウト、エラー分類、ログイベント、テスト方針が記載されている

## 完了条件

### 方針と実行機構

- [ ] 設計で定義した方針を表現し、文書チャンクのEmbedding要求向けの実行制御へ渡せるHaskell型または設定境界が実装されている
- [ ] 1回の試行を表す処理を受け取り、成功結果または共通エラーを返す再試行の実行機構が実装されている
- [ ] 設計で定義した範囲へタイムアウトを適用し、規定時間内に完了しない試行または処理種別を共通エラーとして扱える
- [ ] 一時的失敗かつ再試行しても安全と分類された場合だけ再試行する
- [ ] 入力不正、契約違反、不正なレスポンス、永続的なモデル失敗など、設計で再試行しないとした失敗を追加試行せず返す
- [ ] 最大試行回数、待機、バックオフ、ジッター、時間上限など、採用した方針が設計どおりに適用される

### ログと最終エラー

- [ ] 再試行予定、再試行後の成功、試行上限到達、タイムアウト、再試行しない失敗について、設計で定義した構造化ログイベントを共通ログ基盤へ渡せる
- [ ] 同じ論理的な処理に属する各試行を、設計した実行との関連情報と試行番号によって追跡できる
- [ ] 試行上限へ達した場合に、最後の失敗原因と試行経過を失わず、呼び出し元へ返せる

### RS-0004との統合境界

- [ ] 再試行の実行機構から、具体的なHTTPクライアント、JSON型、Pythonモデル実装への依存が分離されている
- [ ] RS-0004が1回のHTTPリクエストを表す処理を渡し、独自の再試行処理を持たずに実行機構を利用できる公開境界がある

### テスト・設計反映・整合

- [ ] 初回成功では追加試行を行わないことを自動テストで確認できる
- [ ] 一時的失敗後に成功する場合、設計した回数と待機で再試行して成功結果を返すことを自動テストで確認できる
- [ ] 再試行しない失敗では追加試行を行わないことを自動テストで確認できる
- [ ] 試行上限到達時に最終エラーを返すことを自動テストで確認できる
- [ ] 設計で採用した各タイムアウトが発生した場合の中断とエラー変換を自動テストで確認できる
- [ ] 再試行とタイムアウトのテストが長い実待機や不安定な実時間へ過度に依存せず、安定して実行できる
- [ ] 再試行に関係する構造化ログイベントと実行との関連情報をテスト用出力処理で確認できる
- [ ] 実装で具体化または変更された現在設計が`design/リトライ・タイムアウト設計.md`、`design/エラー設計.md`、`design/構造化ログ基本設計.md`へ反映されている
- [ ] 実装、各設計書、共通エラー・構造化ログ基盤に解消していない差異がない
- [ ] プロジェクトで定めたRAGScopeアプリケーション側のテストコマンドを実行し、追加したテストを含めて成功する

## 対象外

- AI推論サービスの文書チャンクのEmbedding生成API実装
- 文書チャンクのEmbedding要求に使用するHaskellのリクエスト・レスポンス型とJSON変換
- 入力した文書チャンクと返却されたEmbeddingの対応検証
- RS-0004における実HTTPクライアントへの統合
- 文書チャンクのEmbedding要求以外の処理種別への再試行・タイムアウト適用
- PostgreSQL処理のトランザクション、`unique`制約、`upsert`
- 大規模なバッチ処理、並列リクエスト、非同期ジョブ
- CloudWatch固有の収集・監視設定
- 分散追跡（tracing）の正確なSpan構造と処理間の関連付け規則

## 実装メモ

- 実行機構は対象の処理種別で直ちに使う能力だけを実装し、未使用の戦略や提供元固有の選択肢を増やさない。
- 1回のHTTPリクエストを表す処理の実装はRS-0004が担当し、本Ticketはその処理の反復、待機、タイムアウト、終了判断を担当する。
- 待機、時刻、乱数などをテスト可能にする方法はRS-0016の設計に従い、テストのためだけに本番APIを不必要に複雑化しない。
- エラー分類は対象の処理種別から与えられる判断を使用し、実行機構自身がすべてのHTTPステータスやアプリケーションエラーを知る構成にしない。
