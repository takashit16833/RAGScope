# v0.0 固定Markdown文書の取り込みとチャンク化

## 能力

RAGScopeアプリケーションでv0.0に使用する固定Markdown文書を読み込み、事前に定めた固定ルールで検索に使用する複数の文書チャンクへ分割し、後続のEmbedding生成へ渡せる。

各文書チャンクは、元の本文を保持したまま、元文書と文書内での順序を識別できる形で扱う。

## Milestoneでの役割

### dense検索の入口としての責務

v0.0では、固定Markdown文書から検索対象となる文書チャンクを作成し、Embeddingの生成・保存を経て、質問に近い文書チャンクを取得する最小のdense検索経路を完成させる。

このEpicはその入口を担当し、入力文書を後続のEmbedding生成が受け取れる単位へ変換する。

### 後続Epicとの境界

Embeddingの生成と保存、およびdense検索の実行は、v0.0の後続Epicで扱う。

文書や分割条件のバージョン管理、正規化済み本文の保存、元文書内の厳密な位置管理、複数のチャンク条件の比較は、このEpicでは扱わず後続Milestoneで追加する。

### 共通基盤との関係

本Epicの実装Ticketは、[Observability設計](../../../../design/observability/README.md)と[文書処理設計](../../../../design/features/文書処理設計.md)に従う。RAGScopeアプリケーションでTelemetryを記録する実装は、[RS-0024](<../error-logging/RS-0024 RAGScopeアプリケーションへOpenTelemetry Observability最小基盤を実装する.md>)が提供するTelemetry利用境界を使用し、独自のLogging Runtimeや共通ログ形式を追加しない。

文書読み込みとチャンク化では自動再試行を行わず、これらの処理に固有の再試行・タイムアウト実行機構を本Epicへ先行実装しない。

## 完了条件

### 文書読み込み

- [ ] RAGScopeアプリケーションでv0.0に使用する固定Markdown文書を読み込める
- [ ] 文書の読み込みに失敗した場合、正常時と区別して原因を確認できる

### チャンク化と不変条件

- [ ] 読み込んだ本文を、事前に定めた固定ルールで1件以上の文書チャンクへ分割できる
- [ ] 各文書チャンクが元のMarkdown本文の内容を保持している
- [ ] 各文書チャンクについて、元文書と文書内での順序を識別できる
- [ ] 生成した文書チャンクを、後続のEmbedding生成処理へ渡せる

### 失敗・Observability・再試行

- [ ] 文書処理で発生する失敗を、文書処理固有の具体的なerror typeとして正常結果と区別して扱える
- [ ] 文書読み込みとチャンク化のTelemetryが、[実行追跡設計](../../../../design/observability/実行追跡設計.md)と[ログ・イベント設計](../../../../design/observability/ログ・イベント設計.md)の共通規則に従い、同じ事実をSpanとEventRecordへ重複記録していない
- [ ] 文書読み込みとチャンク化で自動再試行を行わないことと、その理由が設計と実装から確認できる

### 検証

- [ ] 文書読み込みとチャンク化の正常系・異常系を、テストまたは実行によって確認できる
