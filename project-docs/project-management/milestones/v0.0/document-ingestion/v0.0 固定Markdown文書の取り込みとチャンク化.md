# v0.0 固定Markdown文書の取り込みとチャンク化

## 能力

RAGScopeアプリケーションでv0.0に使用する固定Markdown文書を読み込み、事前に定めた固定ルールで検索に使用する複数のチャンクへ分割し、後続のEmbedding生成へ渡せる。

各チャンクは、元の本文を保持したまま、元文書と文書内での順序を識別できる形で扱う。

## Milestoneでの役割

v0.0では、固定Markdown文書から検索対象となるチャンクを作成し、Embeddingの生成・保存を経て、質問に近いチャンクを取得する最小のdense検索経路を完成させる。

このEpicはその入口を担当し、入力文書を後続のEmbedding生成が受け取れる単位へ変換する。Embeddingの生成と保存、およびdense検索の実行は、v0.0の後続Epicで扱う。

本Epicの実装Ticketは、[共通エラーと構造化ログによる実行追跡Epic](<../error-logging/v0.0 共通エラーと構造化ログによる実行追跡.md>)が完了し、[ADR-0002 — 共通実行基盤の契約とコンポーネント実装を分離する](<../../../../docs/adr/ADR-0002 共通実行基盤の契約とコンポーネント実装を分離する.md>)で定めたretry / timeoutの共通原則を`文書処理設計.md`へ適用した後に進める。文書読み込みでは自動retryを行わず、operation固有のretry / timeout設計やexecutorを本Epicへ先行実装しない。

文書や分割条件のバージョン管理、正規化済み本文の保存、元文書内の厳密なoffset管理、複数のチャンク条件の比較は、このEpicでは扱わず後続Milestoneで追加する。

## 完了条件

- [ ] RAGScopeアプリケーションでv0.0に使用する固定Markdown文書を読み込める
- [ ] 読み込んだ本文を、事前に定めた固定ルールで1件以上のチャンクへ分割できる
- [ ] 各チャンクが元のMarkdown本文の内容を保持している
- [ ] 各チャンクについて、元文書と文書内での順序を識別できる
- [ ] 生成したチャンクを、後続のEmbedding生成処理へ渡せる
- [ ] 文書の読み込みに失敗した場合、正常時と区別して原因を確認できる
- [ ] 文書読み込みとチャンク分割の正常系・異常系を、テストまたは実行によって確認できる
- [ ] 文書処理で発生する失敗が、共通エラー契約へ対応付けられている
- [ ] 文書処理の開始、完了、失敗を、共通ログ基盤から一連の実行として追跡できる
- [ ] 文書読み込みとチャンク化で自動retryを行わないことと、その理由が設計と実装から確認できる
