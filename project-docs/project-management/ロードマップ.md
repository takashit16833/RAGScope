# RAGScopeロードマップ

> [!abstract] この文書の役割
> RAGScopeがどのようなリリース可能なバージョンを経て発展するかを示す。  
> 要求の正本は[RAGScope要求定義](../RAGScope要求定義.md)、現在のシステム構成は[システムアーキテクチャ](../design/システムアーキテクチャ.md)を参照する。

## 1. 進め方

- 各Milestoneは、単独で実行または検証でき、Git tagを付けられる状態とする。
- Epic・Ticketへの具体化は[RAGScopeプロジェクト管理規約](../rules/RAGScopeプロジェクト管理規約.md)に従う。
- 各Milestoneの成功条件を満たすまで、後続機能を現在の作業へ混ぜない。
- ローカル実行可能性を維持しながら、AWSへの配置も必須の到達点として段階的に実現する。
- 将来構成は、先行する実装や実験の結果を確認してから決定する。

## 2. バージョン計画

### [v0.0 — 最小のdense検索を実行できる](./milestones/v0.0/v0.0.md)

少量の固定Markdown文書を固定ルールで文書チャンクへ分割し、文書チャンクのEmbeddingを保存する。RAGScope CLIから質問を入力し、近似インデックスを使わないベクトル検索（exact vector search）で、質問に近い文書チャンクを表示できる状態にする。あわせて、共通エラー・構造化ログ契約と、必要な再試行・タイムアウト処理の最小基盤を整える。

### v0.1 — 検索実験を保存・評価・比較できる

評価問題、文書の正規化と位置情報、文書・データ・設定のバージョン管理、質問ごとの検索結果保存を追加する。全文検索を比較基準（baseline）としてdense検索と同じ評価データで比較し、検索指標とMarkdown / CSV形式のレポートから違いを説明できる状態にする。

### v0.1.5 — AWSへ最小構成を配置・検証できる

AWS配置の最初の必須到達点として、Embedding処理を含む小さな構成をAWSへ作成・接続・削除する。CloudFormation、EC2、RDS、S3、IAM、Session Manager、Secrets Manager、CloudWatchを利用し、通信経路、権限、料金、成果物の退避、削除後の残存物を説明できる状態にする。v0.0で整備した構造化ログをCloudWatchへ収集し、同じ実行に関係するイベントを検索できることも確認する。

### v0.2 — 利用者が管理する環境で回答と引用を生成できる

検索した文書チャンクを回答生成へ渡す`context`として、利用者が管理する環境で動かすモデルから回答を生成する。生成条件、プロンプト、`context`、回答、構造化引用を保存し、文書から回答できない質問への拒否も扱える状態にする。

### v0.3 — hybrid検索とrerankingを比較できる

全文検索とdense検索の結果を統合するhybrid検索と、Cross Encoderによる`reranking`を追加する。適用前後の検索精度、取得内容、追加処理時間を同じ評価データで比較できる状態にする。

### v0.4 — 回答・引用・回答可能性を評価できる

参照回答（`reference answer`）を利用して、回答の根拠忠実性（`faithfulness`）、正確性、関連性、引用の正確性を評価する。回答可能（`answerable`）／回答不能（`no-answer`）の判定も含め、検索精度だけでなく最終回答の品質を比較できる状態にする。

### v0.5 — 実験基盤としての信頼性と観測性を備える

v0.0で導入した共通エラー・構造化ログと、処理種別（`operation`）ごとの再試行・タイムアウトを実験基盤向けに拡張する。Embeddingのキャッシュ、分散追跡（tracing）、バッチ処理、非同期ジョブ、性能集計、障害時の挙動を整備し、正常時の精度だけでなく、処理時間、成功率、失敗原因と処理間の関係を追跡できる状態にする。

### v1.0 — 第三者が再現できる公開版を完成させる

README、構成図、API仕様、必要なADR、サンプルデータ、比較レポート、再現手順、制約、既知の問題、モデルとデータセットのライセンス、CIを整備する。第三者がローカル環境でサンプルデータの取り込みから実験レポート生成まで実行でき、AWSの最小構成も公開された定義と手順から再構築・検証できる状態にする。

### v1.1 — AWS上の次の構成を判断する

v0.1.5のAWS配置結果とv1.0の完成結果を確認し、EC2上のコンテナ、ECR、ECS / Fargateへ構成を拡張するかを判断する。AWS構成を追加しても、高可用性や大規模運用を実現したとは主張しない。
